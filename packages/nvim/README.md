# nvim

Next.js（TypeScript / React / CSS Modules）での開発を主目的とした Neovim 設定。

- **Neovim 0.12 以降が必須**（`vim.lsp.config` / `after/lsp/` / `vim.pack` などの前提）
- 端末は Ghostty または Alacritty ＋ tmux を想定
- リーダーキーは `Space`

関連: [Vim / Neovim 入門](docs/vim.md) ／ [操作の練習](docs/practice.md) ／ [tmux の操作](docs/tmux.md) ／ [ウィンドウ操作（yabai + skhd）](docs/window.md)

## 構成

```
.
├── init.lua                  リーダーキーの定義と各モジュールの読み込みのみ
├── lua/
│   ├── config/               プラグインに依存しない設定
│   │   ├── options.lua       vim.opt 系
│   │   ├── filetype.lua      拡張子の判定（.mdx など）
│   │   ├── keymaps.lua       プラグイン非依存のキーマップ
│   │   ├── autocmds.lua      自動処理（IME 切替、巨大ファイル対策など）
│   │   ├── commands.lua      :ConfigReload
│   │   ├── highlights.lua    配色の調整（全テーマ共通 + iceberg 専用）
│   │   ├── codediff.lua      差分のタブを入口ごとに1枚に保つ
│   │   ├── zoom.lua          窓の最大化のトグル
│   │   ├── oil-git.lua       ファイラに git の状態を出す
│   │   ├── projects.lua      <Space>fp に並べるプロジェクト
│   │   ├── practice.lua      :Practice の教材を複製して開く
│   │   ├── snippets.lua      自作スニペットの読み込みと一覧
│   │   ├── math_source.lua   数式定義を補完する blink のソース
│   │   └── lazy.lua          lazy.nvim のブートストラップ
│   └── plugins/              カテゴリ単位のプラグイン定義
├── after/lsp/                LSP サーバごとの設定
├── snippets/                 自作スニペット（VSCode 形式）
├── data/                     LSP に渡す補助データ
└── lazy-lock.json            プラグインのバージョン固定
```

### 設計の方針

**素の Vim のキーは、原則として意味を変えない。** サーバーに入った時に手が誤作動しないようにするため。

改造には2種類ある。

| 種類 | 例 | 素の Vim を触った時 |
|---|---|---|
| **足す** | `<Space>ff` `ysiw"` `grn` | 無いだけ。指は誤作動しない |
| **書き換える** | `H` をバッファ移動にする | **同じキーが違う結果を出す** |

**新しい機能は空いているキーに載せる**（`<Space>` 系、`]` `[` 系、素の Vim で使わないキー）。書き換えを検討する時は、次の3つで判断する。

| 観点 | 問い |
|---|---|
| **頻度** | そのキーを素の Vim でどれだけ使うか |
| **実害** | 間違えて押した時に何が起きるか。何も起きないのか、状態が変わるのか |
| **代替** | 潰した動作を別の手で賄えるか |

3つとも軽ければ書き換えてよい。実例として、ビジュアルモードの `J` `K`（行の連結 / ヘルプ引き）は選択行の上下移動に差し替えてある。連結は `3J` で代替でき、ヘルプ引きはビジュアルではほぼ使わないため。

逆に外したものが3つある。

- **`H` `L` → バッファ移動** — 素では「画面の最上行 / 最下行へ」という毎日使う移動。`]b` `[b` で足りる
- **`-` → ファイラ** — `<Space>e` と同じ動作を2箇所に置いていた
- **nvim-spider（`w` `e` `b` を camelCase 単位に）** — Vim には「`cw` だけは語の末尾で止まる」という特別扱いがあり、`w` を差し替えると失われる。`(a, b)` の `a` で `cw` を押すと `, ` まで消え、`a + b` では空白まで消えた。**40年ぶんの例外がキーの側に埋まっている**ので、動詞と範囲の対応そのものは触らない

camelCase の一部を直したくなった時は、`ctU`（`U` の手前まで変更）や `grn`（LSP の名前変更）で足りる。どうしても要るならテキストオブジェクト（`iu` など空いているキー）として足せば、「足す」側に変換できる。

**キーマップは2箇所に分ける。** プラグインに依存しないものは `config/keymaps.lua`、プラグイン固有のものは各プラグイン定義の `keys = {}` に置く。後者にしないと lazy.nvim の遅延ロードが効かず起動が遅くなる。

**LSP の設定は `after/lsp/` に置く。** Neovim は `runtimepath` 上の `lsp/<name>.lua` をすべてマージするため、nvim-lspconfig が配る既定値と自分の設定が同列に扱われる。`after/lsp/` なら確実に後から読まれ、上書きできる（`:help lsp-config-merge`）。

**プラグインはカテゴリ単位のファイルにまとめる。** 1プラグイン1ファイルにすると数が増えすぎて把握しづらい。

## セットアップ

### 新しい Mac で再現する

```bash
git clone https://github.com/Harunosuke-web/dotfiles ~/.dotfiles
ghq get Harunosuke-web/nvim          # ~/Repos/github.com/Harunosuke-web/nvim へ
~/.dotfiles/scripts/setup.sh          # brew / stow / nvim のリンクまで一括
nvim                                  # プラグインと LSP が自動導入される
```

`setup.sh` の中で `setup-nvim.sh` が `~/.config/nvim` へのシンボリックリンクを張る。

### 前提となる外部コマンド

| コマンド | 用途 | 導入 |
|---|---|---|
| `tree-sitter` | パーサのビルド（**main ブランチでは必須**） | `brew install tree-sitter-cli` |
| `rg` | 全文検索 | `brew install ripgrep` |
| `fd` | ファイル検索 | `brew install fd` |
| `fzf` | 絞り込み | `brew install fzf` |
| `lazygit` | Git クライアント | `brew install lazygit` |
| `node` | LSP サーバの多くが Node 製 | mise |
| `macism` | 日本語入力の自動解除 | `brew install macism` |

LSP サーバと整形ツールは mason が自動導入する。手動操作は不要。
Copilot の言語サーバもここに含まれる。認証だけは `:Copilot auth` を1度打つ必要がある。

### 設定を変えたときの反映

| 変更した場所 | 反映方法 |
|---|---|
| `lua/config/*.lua` | `:ConfigReload` |
| `after/lsp/*.lua` | `:lsp disable <名前>` → `:lsp enable <名前>` |
| カラースキーム | `:colorscheme <名前>` |
| `lua/plugins/*.lua` の `opts` | **再起動が必要** |
| プラグインの追加・削除 | `:Lazy sync` の後に再起動 |

`:source $MYVIMRC` は効かない。`init.lua` が `require()` で各モジュールを読んでおり、2回目以降は Lua のモジュールキャッシュが返るだけで再実行されないため。`:ConfigReload` はこのキャッシュを明示的に捨てている。

`:lsp restart` だけでは `after/lsp/*.lua` の変更を拾わない（`vim.lsp.config` が解決済みの設定をキャッシュするため）。`restart` はサーバが固まった時の復帰用。

## 使い方

Vim そのものの操作（モード、`d` / `c` / `y` と範囲の組み合わせ、テキストオブジェクト）は [Vim / Neovim 入門](docs/vim.md) にまとめてある。手を動かして覚えたい時は `:Practice`（→ [操作の練習](docs/practice.md)）。ここではこの設定に固有の使い方を扱う。

### 起動する

**引数なしで `nvim` を実行すると、差分のレビューかファイラのどちらかが出る。** 開くのは片方だけ。

| 状況 | 出るもの |
|---|---|
| リポジトリ内で、変更が残っている | 差分のレビュー（codediff） |
| リポジトリ内で、変更が無い | ファイラ |
| リポジトリの外 | ファイラ |
| ファイル名を指定した（`nvim foo.ts`） | そのファイル |

手ぶらで開くのは「何をしていたか思い出す」場面なので、変更が残っていればそれ自体が答えになる。
**レビューを `q` で閉じるとファイラが出る。** そのまま次の作業へ移れる。

**専用の起動画面は持たない。** 項目がどれも別の入口と重なっていたため。
ファイル探索は `<Space>ff`、最近開いたファイルは `<Space>fr`。

### 外部でファイルが変わったとき

**AI エージェントや `git` の操作でファイルが書き換わると、自動で読み直す。** 画面に戻った時・別のバッファへ移った時・手を止めた時に検知する。読み直しが起きた時はファイル名つきの通知が右上に出るので、黙って中身が変わることはない。

ファイラ（oil）も同じように追従する。開いているディレクトリでファイルが増減すれば、一覧がその場で更新される。

**自分の編集が残っている場所を書き換えられた時は、差分で突き合わせる。**
素の Neovim は「読み直す / 捨てる」の二択を迫るが、どちらを選んでも片方が消える。
代わりに確認を出さず、バッファを保ったままディスクの内容を右に並べて開く。

| | |
|---|---|
| 左 | 今のバッファ（未保存の変更あり） |
| 右 | ディスクの内容。`buftype=nofile` なので保存されない |

取り込み方は画面下端に出る。`do` で右の行を引き、`]c` `[c` で次の差分へ移り、`:w` で確定して `:tabclose` で閉じる。
差分が自動で開くのは今見ているバッファだけ。他のファイルは通知だけ出るので、`:DiffDisk` で後から開く。

### コードを読む

**今どこにいるか**は2箇所に出る。
画面最上部のタブ行に、開いている**タブページ**が並ぶ。
今いるタブは本文と同じ明るさに太字、他は一段落とした色になる。
分割している時は、各ウィンドウの右上にもファイル名が出る。

```
 1 README.md │ 2 page.tsx │ 3 route.ts
```

番号とファイル名が並ぶ。未保存があれば `[+]` が付く。
タブが1枚だけの間はタブ行を出さない。

並ぶのはバッファではない。**バッファは一覧から選ぶ**（`<Space><Space>`）。

**このファイルの中の構造をたどる**なら `<Space>gs`（シンボル一覧）か `<Space>xs`（右側にシンボルツリー）を使う。

**定義や参照へ移動する。**

よく使うものは2打鍵でも押せる。どちらも同じものを呼ぶ。

| 動作 | 2打鍵 | `<Space>` 系 |
|---|---|---|
| 定義へジャンプ | `gd` | — |
| 参照一覧 | `gr` | `<Space>gr` |
| 実装へジャンプ | `gI` | `<Space>gi` |
| 型定義へジャンプ | `gT` | `<Space>gt` |
| このファイルのシンボル一覧 | — | `<Space>gs` |
| プロジェクト全体のシンボル検索 | — | `<Space>gS` |
| ホバー（型やドキュメントを表示） | `K` | — |
| 移動履歴を戻る / 進む | `<C-o>` / `<C-i>` | — |

候補が1件なら即ジャンプし、複数あればプレビュー付きの一覧が出る。

**2打鍵が大文字になっているものは、小文字を温存したため。** `gi` は前回の挿入位置、`gt` は次のタブページで、どちらも使う。
逆に `gd`（ローカル宣言のテキスト検索）と `gr`（仮想置換）は LSP が上位互換か代替があるので潰した。

定義へのジャンプに `<Space>` 系は無い。
2打鍵で足りるうえ、`<Space>g` は Git の操作で埋まっているため。

`gr` は即発火させるために `nowait` を付けている。
そのため Neovim 標準の `grn`（リネーム）と `gra`（コードアクション）は届かない。
移設先は `<Space>cr` と `<Space>ca`。

CSS Modules も追える。`styles.title` の上で `gd` を押すと `page.module.css` の該当クラスへ飛ぶ。

**同じ識別子を見つける。** カーソルを識別子の上に置くと、画面内の同じものが自動で薄くハイライトされる。
LSP が使える場面では「同じ綴りの別物」を除いた正確な参照だけが光る。
移動のキーは張っていない。素の `]]` `[[` のセクション移動を潰さないため、一覧が要るなら `gr` を使う。

**関数の間を移動する。** `]f` / `[f` で次・前の関数の先頭へ。`]F` / `[F` で末尾へ。

### コードを書く

**補完が自動で出るかどうかは、カーソル直前の1文字で決まる。** ファイルの種類では分けていない。

| 直前の文字 | ポップアップ | ゴーストテキスト |
|---|---|---|
| 英数字・記号・行頭 | **自動で出る** | 出る |
| ひらがな・カタカナ・漢字・全角 | **出ない。`<C-Space>` で開く** | 出ない |

日本語を打っている最中にポップアップが開閉するのが煩わしいため止めている。日本語には語の区切りが無く、1文字打つたびに文がまるごと候補になってしまうのも理由。

**判定は文字の符号で行っており、IME の状態は見ていない。** 毎打鍵で入力ソースを問い合わせるには外部コマンドの起動が要るため。日本語の文中で英単語を打ち始めれば、その時点から出る。逆にコードの中の日本語コメントでは止まる。

| 状況 | 自動で出るか |
|---|---|
| `lua` で `local x = fo` | 出る |
| `lua` で `-- これは日本` | 出ない |
| `lua` で `-- これは test` | 出る |
| `markdown` で `This is a te` | 出る |
| `markdown` で `これは日本語` | 出ない |

**AI の候補は打たなくても出る。** blink のゴーストテキストは「打った文字で絞った候補の1件目」なので、何も打っていない状態では出しようがない。
Copilot は文脈から続きを予測するので、行頭でも出る。
止める条件は blink と同じで、直前が日本語なら出ない。

| キー | 動作 |
|---|---|
| `<M-l>` | 候補を丸ごと受け入れる |
| `<M-Right>` | 1語だけ受け入れる。予測が途中まで合っている時に |
| `<M-]>` / `<M-[>` | 次 / 前の候補 |
| `<C-]>` | いまの候補を捨てる |

**blink のメニューが開いている間は出ない。** 薄い文字と候補窓が場所を取り合うため。

初回は `:Copilot auth` で認証する。ワンタイムコードがクリップボードに入るので、出た URL で貼る。
資格情報は `~/.config/github-copilot/auth.db` に置かれ、このリポジトリには入らない。
`:Copilot status` で状態、`:Copilot disable` で止められる。

**状態を見るときは実ファイルのバッファで打つこと。** `:checkhealth` の画面は `buftype` が空でないため、
Copilot は接続せず `not attached based on should_attach config` と出る。異常ではない。

**言語サーバは mason が入れる**（`copilot-language-server`）。起動と接続は copilot.lua が受け持つ。
mason-lspconfig の自動有効化からは外してある。両方が立てるとクライアントが二重になり、
後から起動した側が先客を落として `exit code 143` の警告が出る。

サーバは 545MB ある。うまく動かないときは `~/.local/state/nvim/copilot-lua.log` を見る。

**止めているのは自動表示だけ**で、補完そのものは働いている。`<C-Space>` を押せばいつでも開く。

| キー | 動作 |
|---|---|
| `Tab` | **確定** |
| `<C-n>` / `<C-p>` | 次 / 前の候補（ポップアップを開いていなくても効く） |
| `↓` / `↑` | 同上 |
| `<C-Space>` | ポップアップを開く |
| `<C-e>` | 閉じる |
| `<C-k>` | シグネチャ（引数の説明）を表示 |
| `<C-l>` | スニペットだけに絞った一覧 |
| `<M-l>` | AI の候補を受け入れる（[上記](#コードを書く)） |

候補は LSP・ファイルパス・自作スニペット・バッファ内の単語・数式定義の id から集める。

**`<Space>ff` / `fg` の範囲は git のルート配下。** 別のプロジェクトを触る時は `<Space>fp` で移動する。`lua/config/projects.lua` に書いたディレクトリが上に並び、その後ろに zoxide が覚えている訪問先が続く（重複するものは出ない）。選ぶとそこへ移動し、**ファイラ（oil）が開く**。中身を見ながら辿れる。ファイラのバッファは離れると捨てられるので、開き直す時は `<Space>e` を押す。

```lua
-- lua/config/projects.lua
M.roots = { '~/Projects', '~/Repos/github.com/Harunosuke-web' }  -- 自身と配下を並べる
M.paths = { '~/.dotfiles' }                                       -- 単体で足す
```

**どこにあるか思い出せない時は `<Space>Ff`（ファイル名）と `<Space>Fg`（全文）。** `~/Repos` `~/Projects` `~/.dotfiles` をまとめて探す（約1,200件）。この3つは git の管理下なので、`node_modules` などは `.gitignore` に従って最初から外れる。

プロジェクト以外（書類や設定）まで探すなら `<Space>FF` と `<Space>FG`。ホーム以下をなめる。写真・フォント・書庫・バイナリのデータは除外してあるので、開いて意味のあるものだけが並ぶ（6万件 → 3千件）。

### スニペットの穴を渡り歩く

スニペットを展開すると `${1:...}` の位置に順に止まる。**この時 `Tab` と `Enter` の役割が分かれる。**

| キー | ポップアップが開いている時 | 開いていない時 |
|---|---|---|
| `Tab` | **候補を確定** | 次の穴へ |
| `Enter` | **次の穴へ** | 次の穴へ（穴が無ければ改行） |
| `<S-Tab>` | 前の穴へ | 前の穴へ |

**穴に値を打つと補完が開くため、`Tab` は候補の確定に取られる。** そのまま次の穴へ進みたい時は `Enter` を使う。値を打った直後は `Enter`、何も打たずに飛ばす時は `Tab`、と覚えればよい。

穴は**中身が選択された状態**で止まるので、打てば置き換わる。`Del` で消せば、その属性ごと消える。

```
box       →  <Box label="ラベル">
                       ~~~~~~ ここが選択された状態

打つ    → 置き換わる
Enter   → 次の穴（本文の位置）へ
Del     → label ごと消える
```

### スニペットの呼び出し方

**3通りある。** `;` などの接頭辞は使わない。

| 方法 | 使う場面 |
|---|---|
| 名前をそのまま打つ | 覚えている。補完候補に混ざって出る |
| `<C-l>`（挿入モード） | うろ覚え。**スニペットだけに絞った一覧**が出る |
| `<Space>fs` または `:Snippets` | 何があるか分からない。**中身をプレビューしながら選ぶ** |

**名前は短縮形でも正式名でも、大文字小文字を問わず引ける。** 補完は打った文字を順に拾えるかで照合するため、`thm` は `Theorem` の中に t,h,m として含まれ、どちらでも一致する。

```
thm / Theorem / THM   →  Theorem
callout               →  CalloutNote / CalloutTip / CalloutWarning
box                   →  Box / Box-accent
```

このため**コンポーネント名を知っていれば暗記は要らない。** 何があるか分からなければ `<Space>fs` で一覧を見る。

**追加するには `snippets/<filetype>.json` に VSCode 形式で書く。** ファイル名がそのまま filetype になり、`all.json` は全ファイルタイプで有効。`typescriptreact` では `typescript` と `javascript` の分も候補に出る（`scss` なら `css`、`mdx` なら `markdown`）。

```json
{
  "Console log": {
    "prefix": "clg",
    "body": ["console.log($1);", "$0"],
    "description": "console.log"
  }
}
```

`$1` `$2` が移動する穴、`$0` が最後にカーソルが止まる位置。`${1:既定値}` で初期値を入れられる。**既製のスニペット集（friendly-snippets）は読み込んでいない**ので、候補に出るのはここに書いたものだけ。

今あるスニペットの一覧は [docs/snippets.md](docs/snippets.md) にある。足したらそちらも直す。

**`${1|a,b,c|}` の選択肢は使わない。** Neovim では常に空で展開され、候補を選ぶ画面も無いため、ただの空の穴にしかならない。属性を任意にしたい時は、値ではなく**属性ごと**穴にする（`${1: accent="#0071e3"}`）か、別のスニペットに分ける。

### 数式定義を参照する

ブログの `<MathReference id="..." />` は、**id を覚えていなくても補完から選べる。**

```
mathref  と打つ  →  全件
euler    と打つ  →  euler-formula に関するものだけ
```

選ぶとタグごと完成した形が入る。候補には「定理｜オイラーの公式｜複素数」のように種類・題名・分野が並ぶので、id を知らなくても見分けられる。

id の一覧は blog の `public/math-index.json` を直接読んでいる。**定義を増やせば自動で候補に増える**ため、設定側で登録し直す必要はない。

**タグは自動で閉じる。** `<div>` と打つと `</div>` が入り、開始タグを `section` に書き換えると閉じタグも追従する。

**囲みを操作する。**

| キー | 動作 |
|---|---|
| `ysiw"` | 単語を `"` で囲む |
| `cs"'` | `"..."` を `'...'` に変える |
| `ds"` | `"` を外す |

**構文単位で選択・編集する。**

| キー | 対象 |
|---|---|
| `vaf` / `vif` | 関数（宣言ごと / 中身だけ） |
| `vac` / `vic` | クラス・コンポーネント |
| `vaa` / `via` | 引数 |
| `<Space><CR>` | カーソルを含む構文ノードを入れ子ごとラベル表示し、階層を選んで選択 |

引数の並び替えと引数間の移動（`]a` `[a`）は張っていない。`vaa` で選んで `p` で貼るか、`dd` と `p` で足りるため。

**画面内を移動する。** `<CR>` を押して2文字打つと、該当箇所にラベルが出る。そのラベルキーで飛ぶ。

**保存すると自動で整形される。** prettier / stylua / shfmt をファイルタイプごとに使い分ける。プロジェクトに prettier の設定があればそれを尊重する。一時的に切りたい場合は `:FormatDisable`（`!` を付けるとこのバッファのみ）。

### 検索と置換

**探す範囲は4段階。** キーの大小が広さを表し、小文字から大文字へ進むほど広がる。

| 範囲 | ファイル名 | 全文 | どこを見るか |
|---|---|---|---|
| 今の場所 | `<Space>ff` | `<Space>fg` | `:pwd` の場所 |
| git のルート | `<Space>fF` | `<Space>fG` | `.git` を上へ辿った場所。無ければ今いる場所 |
| 手元のプロジェクト | `<Space>Ff` | `<Space>Fg` | `~/Repos` `~/Projects` `~/.dotfiles` |
| ホーム以下 | `<Space>FF` | `<Space>FG` | `~` 全体 |

**既定が今の場所なのは、`<Space>fp` で移った先をそのまま使いたいため。**
深い場所から開いた時にリポジトリ全体を見たい場合は `<Space>fF` を使う。
今どこを見ているかは、絞り込み画面のプロンプト（`nvim❯` など）に出る。

**ファイル名で見つからない時は `Alt-g` で全文検索へ移れる。** 範囲を選び直さずに切り替わる。

その他の探しもの。

| キー | 対象 |
|---|---|
| `<Space>fb` | 開いているバッファ |
| `<Space>fp` | **プロジェクトを選んで移動**（**P**roject） |
| `<Space>fr` | 最近開いたファイル |
| `<Space>fw` | カーソル下の単語 / 選択した文字列を全文検索（範囲は `<Space>fg` と同じ） |
| `<Space>f/` | 現在のバッファ内 |
| `<Space>fR` | 直前の検索を条件ごと復元 |

**検索結果を一覧として残す。** 検索中に `<C-q>` を押すと、ヒットした全件が画面下部の quickfix に送られる。

```
<Space>fg で検索  →  <C-q> で全件を quickfix へ  →  j / k で流し読み
```

quickfix では `j` / `k` で一覧を上下すると、隣のウィンドウが**その場所へ自動で追従**する。内容を確かめながら探せる。

| キー | 動作 |
|---|---|
| `j` / `k` | 一覧を移動（対象位置が追従表示される） |
| `<CR>` | その場所へ移動（フォーカスも移る） |
| `q` | 一覧を閉じる |
| `<C-j>` | 一覧へ戻る（ウィンドウ移動） |
| `<C-o>` | 移動前の場所へ戻る |
| `]q` / `[q` | 一覧を開かずに次 / 前へ |
| `<Space>uq` | 一覧の開閉 |

**一覧の中で直す。** quickfix の行は、ふつうの文と同じように書き換えられる（quicker.nvim）。行ごとに違う直し方ができるので、同じ名前の一部だけを変えたい時に向く。

| 段階 | 操作 | 書き換わる場所 |
|---|---|---|
| 1 | 一覧の行を書き換える | 一覧だけ |
| 2 | 一覧の窓で `:w` | 各ファイルのバッファ。ディスクにはまだ書かれない |
| 3 | `:wa` | 変更のあった全部のバッファをディスクに保存する |

**2 の後の保存を忘れやすい。** 反映を見てから自分で保存するために、自動では保存しない（`autosave = false`）。2 の前に `q` で閉じようとすると、警告が出て閉じない。2 で、記録した時と中身が違う行は書き戻さず、理由が一覧に差し込まれる。

**置換する。**

| 範囲 | 方法 |
|---|---|
| 現在のバッファ | `:%s/foo/bar/g`（打ちながら結果が分割ウィンドウにプレビューされる） |
| 検索でヒットした全件 | `<C-q>` で quickfix へ送り、`:cdo s/foo/bar/ \| update` |

**専用のプラグインは持たない。** 一括置換の頻度が低く、検索の範囲を4段階で選べるので、
quickfix へ送ってから `:cdo` を流す方が範囲の指定と結果の確認が揃う。
quickfix の一覧はそのまま編集もできる（上の「検索結果を一覧として残す」を参照）。

### Git を扱う

**受け持ちは4つに分かれている。** 同じことを2通りでやらないように、入口を分けてある。

| どこで | 受け持ち | 入口 |
|---|---|---|
| 行の左端（gitsigns） | 編集しながらの確認と取り消し | `]c` `<Space>h*` |
| codediff | 差分と履歴を読む | `<Space>hd` `<Space>g*` |
| lazygit | コミットを組み立てる。push、rebase も | `<Space>gg` |
| shell の `git` | 上の3つに無いもの。cherry-pick、reflog、設定 | tmux の別ペイン |

**編集中の差分は行の左端に出る。** 変更のある行に印が付き、以下の操作ができる。

| キー | 動作 |
|---|---|
| `]c` / `[c` | 次 / 前の変更箇所へ |
| `<Space>hr` | この変更を取り消す（ビジュアル選択中は選んだ行だけ） |
| `<Space>hp` | この変更を吹き出しで確認 |
| `<Space>hb` | この行を書いたコミットを表示 |
| `<Space>hB` | バッファ全体のブレームを横に開く |
| `<Space>ub` | 行ブレームの常時表示を切り替え |
| `<Space>gd` | 変更の中身を本文に重ねて表示（**G**it **D**iff） |
| `dih` | 変更箇所を丸ごと削除（テキストオブジェクト） |

**`<Space>gd` は消えた行も見せる。** 左端の印は「ここが変わった」までしか言わない。
重ねて表示すると、追加された行は緑の帯、消えた行は元の中身が赤い帯で本文に挿し込まれる。
`<Space>hp` の吹き出しと違い、ファイル全体を一度に見渡せる。もう一度押すと消える。

**ブレームは2つある。** `<Space>hb` はその行だけを吹き出しで出す。普段はこちらで足りる。
`<Space>hB` は横に窓を開き、全行の著者と日付を本文と行を揃えて並べる。
件名は幅で切れるので、読む窓ではなく「どこからどこまでが一緒に入ったか」を見る窓として使う。

`<Space>hB` の窓では `r` でその行のコミット時点へ、`R` でその親へ blame を張り直せる。
整形コミットに上書きされた行から、本当の作者まで遡れる。`d` でそのコミットの差分をタブに開く。

**行単位のステージは張っていない。** lazygit の方が確認しながら進められるため。

**このファイル1つを相手にする操作。** どれも codediff のタブで開く。

| キー | 対象 |
|---|---|
| `<Space>hd` | このファイルの差分（**H**unk **D**iff） |
| `<Space>hD` | 同じものを `HEAD~` と比べる |
| `<Space>gh` | このファイルの履歴（**G**it **H**istory） |
| `<Space>gh`（選択中） | 選んだ行を触ったコミットだけ |
| `<Space>gm` | コンフリクトを3方向で解決（**M**erge） |

`<Space>hd` が `h` 側にあるのは、「今いるファイルの変更を見る」という点で左端の操作と地続きのため。
複数のファイルをまとめて見るものは `g` 側に置いてある。

**ブランチを切り替える。** `<Space>gb` で一覧から選ぶ。切り替えるだけなら lazygit を開くより速い。

**コミットを組み立てるのは lazygit。** `<Space>gg` で開く。

### 差分をまとめてレビューする

**変更のあったファイルをツリーに並べ、選ぶと横並びの差分が開く。** 新しいタブに出るので、作業中の画面は崩れない。

**タブは入口ごとに1枚だけ。** 同じキーを押し直すと、組み直さずにそのタブへ飛ぶ。作業ツリーの差分（`<Space>gc`）は常に左端に置かれる。

ファイル単体のものは、対象が変われば開き直す。
別のファイルで `<Space>gh` を押した時に、前のファイルのタブへ飛ばされないようにしている。

| キー | 対象 |
|---|---|
| `<Space>gc` | 作業ツリーの変更（**C**hanges） |
| `<Space>gp` | 派生元からの差分。**P**R と同じ範囲 |
| `<Space>gH` | リポジトリ全体をコミット単位で遡る（**H**istory） |

ファイル1つに絞ったものは前節にある（`<Space>hd` `<Space>gh` `<Space>gm`）。

`<Space>gp` の基準は `origin/HEAD` から引くので、`main` でも `master` でも合う。

**パネルの中の操作。**

| キー | 動作 |
|---|---|
| `j` / `k` | 移動するだけで差分が切り替わる |
| `]f` / `[f` | 次 / 前のファイル |
| `]c` / `[c` | 次 / 前の変更箇所 |
| `t` | 横並び ⇄ インライン（1画面）を切り替え |
| `gc` | 変更のない部分を畳む |
| `-` | ステージ / 解除 |
| `q` | 閉じる |
| `g?` | キー一覧 |

**`]b` は使わない。** 差分ペインのバッファが入れ替わり、左右が別のファイルになる。ファイルを送るのは `]f`。

**`gf` は右隣のタブでファイルを開く。** 差分を左端に残したまま中身を見られる。隣のタブは毎回使い回されるので、タブは増えない。

**差分の配色は `lua/config/highlights.lua` の `DIFF` で決めている。** `:DiffDisk` や `:diffsplit` と同じ `Diff*` グループを使うので、変えれば全部が追従する。

コマンドで打つとさらに絞れる。

```vim
:CodeDiff --staged                 " ステージ済みだけ
:CodeDiff v1.0.1 v1.0.2            " 2つのリビジョン間
:CodeDiff main... -- packages/ui   " パスで絞る
:CodeDiff history HEAD~10          " 直近10コミット
:CodeDiff history % --reverse      " このファイルを古い順に
```

### エラーに対処する

**エラーは行の左端と行内に出る。** 深刻なものが優先表示される。

| キー | 動作 |
|---|---|
| `]d` / `[d` | 次 / 前の診断へ |
| `<C-w>d` | 診断の詳細を吹き出しで表示 |
| `gra` | コードアクション（自動修正の候補） |
| `grn` | リネーム（プロジェクト全体の参照が追従する） |

**一覧で潰す。**

| キー | 対象 |
|---|---|
| `<Space>xx` | 診断一覧（プロジェクト全体） |
| `<Space>xX` | 診断一覧（このファイル） |
| `<Space>fd` | 診断を絞り込み検索 |
| `<Space>xt` | TODO 一覧 |
| `<Space>xs` | シンボルツリー（右側） |
| `<Space>xl` | 定義と参照（右側） |
| `<Space>xq` | quickfix を trouble で開く |

`<Space>x*` は一覧を開いたまま順に潰す用途、`<Space>f*` は絞り込んで1つ選ぶ用途。

**ESLint の自動修正**は `:EslintFixAll`。整形（prettier）とは役割を分けてある。

### 貼り付けとレジスタ

**ヤンクはクリップボードへ入る。** `y` を `"+y` に張り替えてあるので、`yy` で取ったものはそのまま他のアプリに貼れる。

**貼り付けは `p` と `<Space>p` で使い分ける。** 素の `p` は無名レジスタから貼るが、そこは削除でも上書きされる。
選択して `p` で貼り替えると、消えた側が無名レジスタに入る。
同じものを続けて貼ろうとして別の中身が出るのはこのため。
`<Space>p` はクリップボードから貼るので、何度貼っても直前にヤンクしたものが出る。

| 操作 | 貼る元 | 使う場面 |
|---|---|---|
| `p` / `P` | 無名レジスタ（直前のヤンクか削除） | 消した行を別の場所へ移す |
| `<Space>p` / `<Space>P` | クリップボード（直前のヤンク） | 同じものを何度も貼る。他のアプリからも |

**どの操作が何を汚すか。**

| 操作 | 無名 | その他 |
|---|---|---|
| `y` `Y` | 入る | `+`（クリップボード） |
| `dd` `D` `cc` | 入る | `"1`（以降 `"2`…へ押し出される） |
| `dw` `cw` | 入る | `"-`（行未満の削除） |
| `x` | **汚さない** | — |

`x` だけ `"_x`（ブラックホール）に張り替えてある。
打ち間違いの1文字を消す操作で、消した中身を後で貼ることはまず無い。
それでも素の `x` は無名レジスタを上書きするため、貼ろうとしていた内容が消える。

行を消して貼り直すなら `dd` と `p` の組で足りる。
`dd` の中身は `"1` にも残るので、間に別の削除が挟まっても `"1p` で取り戻せる。

### AI エージェントに場所を渡す

**「どこの話か」をパスと行番号の形でヤンクする。** 手で打ち写す手間を省くためのもの。

| キー | 取れるもの |
|---|---|
| `<Space>yf` | git のルートからの相対パスと行番号（`lua/config/keymaps.lua#L42`） |
| `<Space>yp` | 同じものを絶対パスで |
| `<Space>yc`（選択中） | 選んだ範囲を Markdown のコードブロックで |

`<Space>yc` はフェンスに言語名、ファイル名、開始行を付ける。
貼った先で色が付き、何行目の話かも伝わる。

````markdown
```lua filename="lua/config/yank.lua" line=12
local function git_root(path)
```
````

相対パスを既定にしてあるのは、エージェントの作業ディレクトリがリポジトリのルートになるため。
ホームの外の話をする時だけ `<Space>yp` を使う。

### ウィンドウ操作

画面を分ける仕組みは3つの層に分かれている。**どの層を触っているかは修飾キーで分かる。**

| 層 | 修飾キー | 担当 | 詳細 |
|---|---|---|---|
| OS の画面 | `Alt+Shift` / `Ctrl+Alt` | アプリの窓（yabai + skhd） | [ウィンドウ操作](docs/window.md) |
| tmux | prefix | ペインとウィンドウ | [tmux の操作](docs/tmux.md) |
| Neovim | `Ctrl+w` / `<Space>w` / `<Space><Tab>` | 窓とタブページ | この節 |

同じ「分割」でも層が違えば別物。Neovim の中で分割しても OS から見れば1枚の窓のままで、tmux から見れば1つのペインのまま。

#### OS の画面（yabai + skhd）

タイル型のウィンドウマネージャがアプリの窓を自動で並べる。`Alt+Shift` が「見るものを変える」、`Ctrl+Alt` が「窓を動かす」。

| キー | 動作 |
|---|---|
| `Alt+Shift` `h/j/k/l` | 隣の窓へフォーカスを移す |
| `Ctrl+Alt` `h/j/k/l` | 窓そのものを動かす |
| `Alt+Shift` `space` | タイル ⇄ 重ねて最大化 |

`Ctrl + 矢印` は macOS のデスクトップ切り替えに取られていて使えない。詳細と理由は [docs/window.md](docs/window.md)。

#### tmux のペインとウィンドウ

prefix を押してから操作する。ペインが画面の分割、ウィンドウがその集まり。

| キー | 動作 |
|---|---|
| prefix `\` / `-` | 左右 / 上下に分割 |
| prefix `h/j/k/l` | ペインを移動 |
| prefix `C-,` / `C-.` | 幅を狭める / 広げる |
| prefix `z` | ペインを全画面に（もう一度で戻る） |

詳細は [docs/tmux.md](docs/tmux.md)。

#### Neovim の窓

分割・移動・サイズ変更は**素の Vim の `Ctrl+w` に揃っている**。`Ctrl+w` を押すと一覧が出るので、覚えていなくても辿れる。
ペインの分割は入り口が3つ用意してあるので、好きなものを使えばよい。

| キー | 動作 |
|---|---|
| `Ctrl+w` `s` / `v` | 上下 / 左右に分割 |
| `<Space>ws` / `<Space>wv` | 上下 / 左右に分割 |
| `Ctrl+w` `-` / `\` | 上下 / 左右に分割（tmux と同じ指） |
| `<C-h>` `<C-j>` `<C-k>` `<C-l>` | 隣の窓へ |
| `Ctrl+w` `q` / `o` | 閉じる / 他を全部閉じる |
| `Ctrl+w` `=` `+` `-` `<` `>` | 大きさを変える（境界のドラッグでも変わる） |
| `<Space>wz` / `Ctrl+w` `z` | 最大化のトグル |
| `Ctrl+w` `H/J/K/L` | 窓を端へ寄せる（縦並び ⇄ 横並びを変える） |
| `Ctrl+w` `x` / `r` | 窓の中身を入れ替える / 回す |
| `Ctrl+w` `T` | 今の窓を新しいタブページへ出す |

**`<Space>wz` は元の配分に戻せる。** 素の `Ctrl+w _` は最大化できるが、戻すと等分になって元の比率が失われる。こちらは控えを取ってから広げる。最大化したまま隣へ移ると、移った先が最大化される（tmux の `prefix z` と同じ動き）。

#### Neovim のタブページ

画面最上部に並ぶのは**タブページ**。1枚のタブが窓の組み合わせを持つ。

| キー | 動作 |
|---|---|
| `<Space><Tab><Tab>` | 新しいタブ。今のファイルの隣をファイラ（oil）で開く |
| `<Space><Tab>d` / `<Space><Tab>o` | 閉じる / 他を全部閉じる |
| `<Space><Tab>m` | 今の窓を新しいタブへ（`Ctrl+w` `T` と同じ） |
| `gt` / `gT` | 次 / 前のタブ |
| `Ctrl+Shift+h` / `Ctrl+Shift+l` | 次 / 前のタブ |

タブ行にはファイラのタブも `Explorer <ディレクトリ名>` として並ぶ。

#### Neovim のバッファ

タブ行に並ぶのはタブページなので、**バッファは一覧から選ぶ**。

| キー | 動作 |
|---|---|
| `<Space><Space>` | 開いているバッファから選ぶ |
| `]b` / `[b` | 次 / 前のバッファ |
| `Ctrl+^` | 直前のバッファへ往復 |
| `<Space>bd` | 閉じる（分割は保ったまま） |
| `<Space>bo` | 他を全部閉じる |

`Ctrl+^` は2つのファイルを行き来する時に最速。`]b` で辿るより速い。

#### 窓をまたぐ移動

定義や参照へ飛ぶと、別のファイルが同じ窓に開く。**どこから来たかは `Ctrl+o` で戻れる。**

| キー | 動作 |
|---|---|
| `gd` / `gr` | 定義 / 参照へ飛ぶ |
| `gI` / `gT` | 実装 / 型定義へ飛ぶ |
| `gf` | カーソル下のファイルを開く。Next.js の手元の資料では、リンクを辿る（下） |
| `gx` | カーソル下の URL をブラウザで開く |
| `Ctrl+o` / `Ctrl+i` | 飛んだ履歴を戻る / 進む |
| `g;` / `g,` | 編集した場所を戻る / 進む |

**`Ctrl+o` と `g;` は別の履歴を辿る。** 前者は「ジャンプした場所」、後者は「書き換えた場所」。読んでいて迷子になったら `Ctrl+o`、書きかけの場所に戻りたい時は `g;`。

**Next.js の手元の資料（`node_modules/next/dist/docs/`）では、`gf` でリンクを辿る。** 資料のリンクは nextjs.org の道筋（`/docs/app/…`）で、手元のフォルダは番号付き（`01-app/…`）なので、素の `gf` も marksman の `gd` も見つけられない。`lua/config/next_docs.lua` が番号を除いた名前で照らし合わせ、`#見出し` があればそこまで飛ぶ。手元に無いページ（`/docs/messages/…`）は nextjs.org をブラウザで開く

#### 今どの窓にいるか

分割していると見失いやすいので、3つの手がかりを置いてある。

- **カーソル行の帯は、今いる窓にだけ出る**
- **非アクティブな窓は色が沈む**
- **窓の右上にファイル名が出る**（incline）

**保存と終了はコマンドラインから。** `:w` `:q` `:wq` `:q!`、`ZZ`（保存して終了）`ZQ`（保存せず終了）。素の Vim と同じ。

### Markdown を書く

**`<Space>mp` で Chrome の新しいウィンドウにプレビューを出す。** 入力とスクロールが同期するので、書きながら最終形を確かめられる。画像・数式（KaTeX）・Mermaid 図も出る。

| キー | 動作 |
|---|---|
| `<Space>mp` | プレビューの開閉（markdown / mdx のバッファでのみ有効） |

**自動では開かない。** markdown を開くたびにブラウザが出ると邪魔になるため。別のファイルへ移ると自動で閉じる。

**バッファの中で装飾する方式（render-markdown）はやめた。** 画像・数式・図が出ず、書いたものの最終形を確かめられないため。見出しや表の体裁は treesitter の色付けだけが残る。

### ファイルを操作する

`<Space>e` でファイラを開く。**ディレクトリが編集可能なバッファとして開く**ので、通常の Vim 操作がそのまま使える。

| 操作 | やり方 |
|---|---|
| リネーム | 行を書き換えて `:w` |
| 削除 | 行を消して `:w`（ゴミ箱へ移動するので復元可能） |
| 新規作成 | 行を追加して `:w` |
| 複数を一括 | ビジュアル選択して `dd` / `p` など |

**`<Space>j` でプロジェクトの package.json を覗ける。** 画面の8割を占めるフロートで開き、`q` か `<Esc>` で閉じる。
依存名やスクリプト名を確かめるだけなら、窓を割るより速い。
行末には最新版が出るので、更新の要否もその場で分かる。
モノレポでは今のファイルから上に辿って最初に当たったものを開く。

**リネームすると import パスが自動更新される**（LSP 連携）。
書き換えられたバッファのうち、自分が編集していないものは自動で保存される。
保存し忘れて閉じると、改名だけが残って参照の修正が消えるため。

| キー | 動作 |
|---|---|
| `-` | 親ディレクトリへ |
| `_` | 作業ディレクトリへ |
| `<CR>` | 開く |
| `<C-s>` | 縦分割で開く |
| `<C-p>` | プレビュー |
| `g.` | 隠しファイルの表示切替 |
| `g?` | ヘルプ |

## カスタマイズ

### LSP サーバを追加する

1. `lua/plugins/lsp.lua` の `servers` に名前を足す（mason が自動で導入する）
2. 詳細設定が要るなら `after/lsp/<名前>.lua` に書く

```lua
-- after/lsp/gopls.lua
return {
  settings = {
    gopls = { analyses = { unusedparams = true } },
  },
}
```

サーバ名は `:Mason` の一覧、または `:lsp enable <Tab>` の補完で確認できる。

### 整形ツールを追加する

`lua/plugins/format.lua` の `formatters_by_ft` にファイルタイプとツールを足し、`lua/plugins/lsp.lua` の `tools` にツール名を足す（mason が導入する）。

足した後は、ファイルを 1 つ開いてから `:MasonToolsInstall` を打つ。入ったかは、そのファイルタイプのファイルで `:ConformInfo` を開き、ツールが `ready` かで確かめる。

mason-tool-installer は nvim-lspconfig と一緒に、ファイルを開いたときに読み込まれる。立ち上げの合図（`VimEnter`）はそれより先に来るので、ファイル無しで立ち上げると自動の導入は走らない。

### 配色を変える

`lua/config/highlights.lua` の `ICEBERG` テーブルを編集する。5段階の明度で構成されている。

| 用途 | 既定 |
|---|---|
| 本文 | `#0d0e14` |
| 行番号・記号の列 | `#161822` |
| カーソル行・フロート背景 | `#1f2233` |
| フロート内の選択行 | `#292e47` |
| 補助的な文字（`breadcrumb`） | `#7d8296` |

lualine の各要素は `WinBar` の色を読むので、`breadcrumb` を変えれば追従する。

タブ行は `TabLine` / `TabLineSel` から色を作る。選択中のタブは面を持たせず、左端のバー（`Special` の色）と太字で示す。

**どのテーマにも掛かるものと、iceberg だけのものがある。**

| 範囲 | 内容 |
|---|---|
| 全テーマ | 面の透過、カーソル行の帯を左端の列まで伸ばす、差分の配色、分割の境界線とスクロールバーのつまみ、キーワードの斜体、選択中のタブから面を外す、ステータスラインを本文に合わせる |
| iceberg だけ | 上の階層づけ（補完メニュー・Markdown の見出し・タブの番号など、`ICEBERG` の明度を使う指定） |

iceberg 以外に切り替えても、透過と差分の色はそのまま効く。明度で段を作る細かい調整だけが外れる。

### テーマを切り替える

```vim
:colorscheme tokyonight-storm
```

`<Space>fc` ならプレビューしながら選べる。恒久的に変えるなら `lua/plugins/colorscheme.lua` の `vim.cmd.colorscheme('iceberg')` を書き換える。

`<Space>fc` の一覧には Neovim 同梱のもの（`blue` `desert` `habamax` など27個）を出していない。入れたテーマが埋もれるため。打てば使える。

導入済みのものと、暗い / 明るいの対応。

| プラグイン | dark | light |
|---|---|---|
| iceberg | `iceberg`（= `-dark`） | `iceberg-light` |
| tokyonight | `tokyonight`（= `-moon`）、`-night`、`-storm` | `tokyonight-day` |
| kanagawa | `kanagawa`（= `-wave`）、`-dragon` | `kanagawa-lotus` |
| rose-pine | `rose-pine`（= `-main`）、`-moon` | `rose-pine-dawn` |
| catppuccin | `catppuccin-mocha`、`-macchiato`、`-frappe` | `catppuccin-latte` |
| nightfox | `nightfox`、`duskfox`、`nordfox`、`terafox`、`carbonfox` | `dayfox`、`dawnfox` |
| gruvbox / gruvbox-material | 名前は1つ。`background` に従う | 同左 |
| gruvbox-minor / vague | dark のみ | — |

**`background` は `dark` に固定してある。** 明るい配色は面を透過させている都合で本文が読めないため、使うなら名前で明示する。

## 既知の制限

**MDX の LSP が無い。** `mdx-analyzer` は依存する `vscode-uri` の破壊的変更で起動できない（上流未修正）。`.mdx` は Treesitter のハイライトと prettier の整形までは効く。

**Astro は TypeScript 6 以下でしか型の機能が動かない。** Astro の LSP と `astro check` は、TS 7 の npm パッケージから消えた `tsserverlibrary.js` を使う。Astro のプロジェクトでは TS 6 を入れる。

**TypeScript 7 のプロジェクトでは、vtsls ではなく `tsc` が付く。** vtsls はプロジェクトの `tsserver` を使うが、TS 7 には無い。TS 7 の `tsc` は自身が言語サーバになる（`tsc --lsp --stdio`）。プロジェクトの `node_modules/typescript` の版で振り分ける（`after/lsp/vtsls.lua` の `root_dir`）。Next.js の editor 向けの plugin（`tsconfig.json` の `plugins`）は `tsserver` の plugin なので、`tsc` では働かないと思われる（未確認）。

**TS 7 の `tsc` は、カーソル下の単語の強調（documentHighlight）にいつも空で答える。** vim-illuminate が光らせなくなるので、`after/lsp/tsc.lua` で要求を references に差し替え、同じファイルの中の参照だけを光らせている。treesitter に任せると、名前が同じだけの別の変数まで光るため。

**TS 7 の `tsc` には、`import 名前` と打った時点で `from "…"` まで出す補完が無い。** `from "` の後の module の名前の補完はある。本文の補完では、言語サーバは import 先の付いた候補を返すが、エディタで出て import が足されるとは限らない（本人の環境では出なかった。2026-10-29）。設定では入らない。

**Astro のプロジェクトでは、`prettier-plugin-astro` を `.prettierrc` の `overrides` の中に書く。** 一番上の `plugins` に書くと、prettierd はプロジェクトのすべてのファイル（`.ts` も `.css` も）で `Cannot find package .../prettier/index.js` を出して整形できない。`overrides` で `*.astro` にだけ効かせると、prettierd のままで `.astro` も他のファイルも整形できる。

```js
export default {
  overrides: [
    {
      files: "*.astro",
      options: { plugins: ["prettier-plugin-astro"], parser: "astro" },
    },
  ],
};
```

**巨大ファイルでは機能が落ちる。** 1.5MB を超えると Treesitter と LSP を無効化し、Vim の正規表現ハイライトに切り替える。色は残り、補完もバッファ内の単語・パス・スニペットは動く。

**日本語入力からの自動復帰はしない。** 挿入モードを抜けた時などに英字へ切り替えるが、逆方向は `macism` が受け付けないため手動で切り替える。

**イタリックには端末側の対応が要る。** tmux では `tmux-256color` が必要。設定変更後は新しいウィンドウを開けば反映される（サーバの再起動は不要）。

**イタリックの字形は端末のフォント設定で決まる。** この設定ではキーワードだけを斜体にしており、Ghostty 側で `font-family-italic` に別のフォントを当てている。日本語グリフを持たないフォントを指定した場合、日本語は元のフォントへ落ちる。

**`gf` で開いたファイルは隣のタブを使い回す。** 差分から2つ目のファイルを開くと、1つ目のタブが置き換わる。バッファは残るので `]b` や `<Space>fb` で戻れる。

**差分の突き合わせは2方向。** 外部の変更と自分の編集がぶつかった時、共通の祖先が無いため3方向マージはできない。同じ行を両方が変えていた場合は、`do` で取り込むと自分の行が消える（`u` で戻せる）。両方残すなら手で混ぜる。
